B 线先生成一份草稿，再由 judge 判断是否继续查资料。这段循环原本想解决报告依据不够的问题，但九月重新整理 `backend/dual_graph.py`，我觉得有两个地方必须展开讲，否则一张带回环箭头的图很容易把效果说大。

先看 judge 收到了什么。`_judge_report` 的参数只有 query、report 和模型后端，prompt 放的是问题与草稿，没有直接传 `recall_bundle`。草稿生成时读过证据，不代表 judge 又独立对照了一遍证据。它返回 `sufficient` 和 `reason`，程序把原问题与 reason 拼起来，作为下一次检索 query。

```text
问题 + 初始证据 → 草稿
问题 + 草稿 → judge → sufficient / reason
不充分且未到上限 → 用原问题与 reason 补查
```

所以这份判断更接近对草稿的检查。要验证某句话是否忠实于来源，还需要把对应证据明确交给检查过程；当前函数没有完成这一步。

## 追加在后面，截取还在前面

查回新材料以后，代码用 `bundle.extend(extra)` 加到末尾。下一份草稿却只读 `bundle[:graph_snippet_limit]`。如果首轮已经填满这个上限，新加的片段可能一条也没进生成上下文。

用上限为 3 的自拟例子看就很明显：

```text
初始：[A, B, C]
追加：[D, E]
合并：[A, B, C, D, E]
草稿实际读取前 3 项：[A, B, C]
```

日志会出现追加检索，bundle 也确实变长，报告读到的仍是旧三条。遇到这种情况，继续要求模型认真参考新增资料没有用，应该先检查选择上下文的代码。这是现存实现的静态观察，还没有在这里修掉，也没有拿它推算过去演示的效果。

循环使用 `B_MAX_EXTRA_RETRIEVAL` 限制追加次数，默认五次。judge 表示充分会停止，查不到新增材料也会提前退出。代码中空结果退出后有一条状态文案仍写“首轮依据已够用”，与实际的不足判断不一致，读日志时要特别区分。到上限也只代表停止追加，不能反过来证明报告已经充分。

`test_llm_judge.py` 目前验证合法 JSON 与解析失败回退，没有覆盖这整条循环。下一步有明确的检查可以补：让初始 bundle 填满上限，再返回一条带独特标记的新证据，查看下一次草稿的实际 prompt 有没有它。这个问题和医学判断无关，用普通示例文本就能测清楚。

问诊场景里还有一类缺口只能继续问用户。资料库能查一般知识，不能告诉系统这次不适持续了多久。A 线仍要收集这些信息，B 线追加再多检索，也不能把它们补成用户已经说过的事实。本文只讨论教学 demo 的执行路径，不作为诊断依据。
